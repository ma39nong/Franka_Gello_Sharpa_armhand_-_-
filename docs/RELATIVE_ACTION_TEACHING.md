# FR3 相对末端动作示教与遥操接入计划

本文记录 `arm-ui` 分支中“盛取动作”示教功能的当前实现、使用方法、安全边界、
验证状态，以及后续接入 GELLO 遥操需要完成的工作。

## 1. 目标与已确认需求

目标是让操作员先手动拖动 Franka FR3 完成一次盛取动作，再把该动作复用到不同
起始位置。因为盛取位置每次可能不同，所以不能直接重放录制时的绝对关节角；系统
需要保存相对于动作起始末端的轨迹，并在新的真实起点重新求解 IK。

当前已确认的操作语义：

- UI 顶部选择左臂或右臂，一次只处理一条机械臂。
- 通过零力矩模式进行真机手动拖动示教。
- 动作可能涉及 J4–J7，也允许实际录制结果包含其他关节。
- 相对动作从触发时的真实末端姿态开始执行。
- 动作应连续通过轨迹帧，不在中间逐点停车。
- 执行结束后保持最终姿态。
- 未来使用脚踏开关触发自动动作。
- 自动动作期间，GELLO 明显移动应立即中断，同时保留独立 STOP。
- 暂不实现循环执行，先完成单次动作的真机验证。
- 当前不做双臂协同规划，但单臂自身的碰撞、关节限位和连续性检查不能省略。

## 2. 当前已经完成

### 2.0 Operator GUI 遥操接入

Operator GUI 现有 `Q`、`W`、`E` 三个预设动作槽，配置文件为
`config/preset_actions.yaml`。当前 Q 对应左臂 `kuai1`、速度 65%，W/E 暂未配置。
触发时使用当前真实 link8 位姿作为相对动作新原点，调用与 Arm UI 一致的
MoveIt KDL `/compute_ik` 对完整轨迹逐帧预检；只有全部通过才由现有遥操 UDP
安全网关执行。动作结束或中断后会重置 GELLO 增量映射并按动作前状态恢复。

### 2.1 点位示教与关节轨迹

原有 Arm UI 已支持：

- 左臂/右臂选择。
- 在零力矩拖动后读取当前七个关节角。
- 点位命名、保存、删除和 YAML 下载。
- 修改保存角度进行小幅微调，修改时不会立即驱动机械臂。
- 将 1–9 个点位编排为任务。
- 配置速度、加速度和 Pilz blend 半径。
- Start 时读取真实起点，并通过 MoveIt Pilz 执行连续关节任务。
- STOP 取消轨迹，完成或取消后保持机械臂姿态。

### 2.2 连续动作录制

Arm UI 下方已经增加“动作示教（相对末端轨迹）”区域，支持：

- 动作命名。
- 10–250 Hz 采样，默认 100 Hz。
- 开始录制、停止并保存、放弃录制。
- 录制期间持续读取七个真实关节角和末端 TF。
- 自动识别活动关节。
- 自动裁剪动作开始和结束处的静止片段。
- 同时保存原始样本与转换后的相对末端轨迹。
- 动作 YAML 下载和删除。

录制使用 `lychee_root` 作为固定基座，所选机械臂的
`left_fr3_link8`/`right_fr3_link8` 作为当前工具坐标系。`world` 只存在于
MoveIt SRDF 的虚拟关节定义中，并不是 robot_state_publisher 实际发布的 TF，
因此不能作为采样基座。

若录制时的末端位姿为 `T_base_tool(t)`，相对动作帧定义为：

```text
T_relative(t) = inverse(T_base_tool(0)) * T_base_tool(t)
```

在新的动作起点执行时，目标末端位姿为：

```text
T_target(t) = T_base_tool_current * T_relative(t)
```

因此同一个动作可以整体平移和旋转到不同起点，而不是重放原始绝对关节角。

### 2.3 IK 验证

每个已保存动作提供“当前位置验证 IK”按钮。该操作：

- 读取当前真实关节角与当前真实末端姿态。
- 调用 MoveIt `/compute_ik` 服务。
- 左右臂分别使用 `left_arm`/`right_arm` 规划组。
- 当前运动学插件为 `kdl_kinematics_plugin/KDLKinematicsPlugin`。
- 第一帧使用真实关节角作为 IK 初值。
- 后续帧使用上一帧 IK 结果作为初值，降低冗余机械臂的解跳变概率。
- 开启 MoveIt 碰撞检查。
- 检查不可达、关节缺失和相邻关节解跳变。
- 验证只计算，不切换控制器，也不发送机械臂运动命令。

独立验证默认最多均匀检查 250 帧，用于快速判断一个动作能否从当前位置复用。

### 2.4 低速试运行

每个已保存动作提供“动作试运行”按钮，试运行速度范围为 5%–100%，默认
15%；“设为原速 100%”只设置速度，仍需经过确认和完整轨迹安全检查。执行流程如下：

1. 从当前真实姿态重新求解动作的每一帧 IK。
2. 检查 IK、碰撞、连续性和生成的关节速度。
3. 如果求解过程中机械臂被移动，则在切换控制器前拒绝执行。
4. 检查第一帧 IK 是否贴近当前真实关节姿态。
5. 自动从零力矩拖动切换到轨迹控制器。
6. 根据原始动作时间和速度比例生成带关节位置、速度及时间戳的完整样条轨迹。
7. 一次性提交给所选机械臂的 `FollowJointTrajectory` 控制器。
8. 完成后保持动作末点；中途 STOP 后保持取消时的位置。

低速试运行的当前限制：

- 只能单次执行。
- 速度只能设为 5%–100%；高于 30% 时显示额外真机风险提示。
- 执行前使用约 120 ms 对称窗口平滑相对末端位置和姿态，并均匀重采样到最高
  30 Hz；原始录制数据保持不变。
- 动作最多 2,000 帧。
- 时间缩放后的执行时间最多 120 秒。
- 第一帧 IK 与真实起点的任一关节偏差不得超过 0.05 rad。
- IK 求解期间任一关节移动超过 0.03 rad，则拒绝切换控制器。
- 相邻 IK 解任一关节跳变超过 0.35 rad，则拒绝执行。
- 根据实际提交给控制器的三次样条检查关节速度和加速度，超过保守限制则拒绝
  执行。

UI STOP 是控制器轨迹取消功能，不是 Franka 硬件急停。

### 2.5 数据位置

数据写入容器中的 `/data/arm_ui`，该目录映射到 `TELEOP_DATA_ROOT`：

```text
/data/arm_ui/waypoints.yaml
/data/arm_ui/routines.yaml
/data/arm_ui/actions/left__<动作名称>.yaml
/data/arm_ui/actions/right__<动作名称>.yaml
```

动作 YAML 同时包含：

- 单位、侧别、创建时间、基座和工具坐标系。
- 实测采样频率、动作持续时间和活动关节。
- 原始时间、七关节角和绝对末端位姿。
- 相对时间、关节增量和相对末端位姿。

## 3. 当前启动与操作方法

假硬件验证：

```bash
./ops/run/run_moveit.sh --fake
```

真机模式：

```bash
./ops/run/run_moveit.sh --real
```

启动脚本会同时启动 Arm UI，并在有图形桌面时自动打开
<http://127.0.0.1:8081>。设置 `ARM_UI_NO_BROWSER=1` 可以禁止自动打开。

建议的真机首次操作顺序：

1. 完成工作区 preflight，确认负载、质心和硬件停止手段。
2. 选择一条机械臂并托住机械臂。
3. 确认进入零力矩拖动模式。
4. 输入动作名称并开始录制。
5. 手动完成一次盛取动作，然后停止并保存。
6. 将机械臂拖到另一个候选起点并保持不动。
7. 先点击“当前位置验证 IK”。
8. 将试运行速度设为 5%，点击“动作试运行”并确认；只有同一动作逐级完成
   5%、10%、15%、30% 验证后，才考虑继续提高速度。
9. 确认动作方向、勺子姿态和 STOP 后，再逐步提高到 10%–15%。

完整 MoveIt/Arm UI 执行模式和 GELLO 遥操模式仍然互斥。GELLO 模式只额外
启动不含控制器的 `moveit-ik`，以及常驻的 `preset-ik` TCP 服务，专门提供只读
`/compute_ik` 预检。按 Q 不会再 `docker compose run` 起一次性容器。

## 5. 独立示教阶段仍需完成

### P0：真机安全验证

- 验证左右零力矩控制器能正确加载、切换和退出。
- 确认机械臂负载、勺子质量和质心配置正确。
- 实际录制一条短盛取动作，检查采样率、TF 丢帧和数据噪声。
- 以 5% 速度完成首次真机复现，并验证软件 STOP 和硬件停止手段。
- 在多个不同起点重复复现，记录成功率、IK 时间和末端误差。

### P1：勺子 TCP 与轨迹质量

当前相对轨迹以 `link8` 为工具坐标系。勺柄较长时，应标定固定的
`scoop_tcp`/`spoon_tip`：

- 测量勺子安装后相对于 `link8` 的固定平移和旋转。
- 将固定变换加入 URDF/Xacro 或受版本控制的标定文件。
- 录制、IK 和复现统一使用勺子 TCP。
- 固定勺子安装方式，若重新安装则重新确认标定。

还需要依据真机效果决定：

- 是否增加位置或四元数滤波。
- 是否需要更严格的速度、加速度和 jerk 限制。
- 是否需要 UI 中的轨迹裁剪、帧曲线和 RViz 预览。
- KDL 在不同起点是否稳定；若冗余姿态漂移或奇异点失败较多，再比较
  TRAC-IK、Pick IK 或 Franka 半解析 IK。

## 6. GELLO 遥操接入状态

### 6.1 统一控制权

统一控制权仲裁已经接入现有 GELLO 安全网关。完整 Arm UI/MoveIt 执行栈仍不与
遥操并行；遥操旁路的 `moveit-ik` 只计算 IK，不具备机械臂控制器。Operator 的
Q/W/E 打到常驻 `preset-ik`（`127.0.0.1:5591`），由它复用已预热的 Arm UI
MoveIt 运行时。

当前单一控制权流程为：

```text
TELEOP（GELLO控制）
  -> ARMED（冻结遥操输出，读取真实起点）
  -> SOLVING（求解和检查完整相对轨迹）
  -> MACRO（自动动作拥有控制权）
  -> REBASE（以真实末点重置遥操增量基准）
  -> TELEOP
```

所有状态都必须保证同一时刻只有一个合法 FR3 命令源。结合本仓库现有安全契约，
相对动作由现有 100 Hz UDP 遥操循环送入统一安全控制通道，不绕过 freshness、
acquisition、关节限位或 slew 检查。

### 6.2 脚踏开关

未来脚踏适配器需要：

- 使用按下沿触发，避免持续踩住时重复启动。
- 做硬件和软件消抖。
- 只有动作已加载、机械臂状态新鲜且控制状态为 TELEOP 时才能触发。
- 踩下后冻结 GELLO 的机械臂输出，读取真实姿态并开始求解。
- 建议自动动作期间再次踩下作为取消，而不是重复触发。
- 脚踏事件只表达操作意图，不能直接绕过仲裁器发送机械臂命令。

### 6.3 GELLO 明显移动即中断（已实现，待真机验收）

自动动作期间停止采用 GELLO 目标驱动机械臂，但仍持续监听 GELLO 状态：

- 动作开始时保存左右 GELLO 基准。
- 监测单关节变化、累计变化和输入速度。
- 当前单关节阈值为 0.08 rad；真机数据出来后再决定是否增加速度与消抖条件。
- 超过阈值立即停止遥操循环中的预设轨迹输出。
- 取消后保持当前真实姿态并进入 REBASE。
- UI STOP、脚踏取消和 GELLO 移动中断使用同一条幂等取消路径。
- 仍需测量从操作员移动 GELLO 到安全网关停止预设输出的最坏延迟。

具体阈值必须根据真实 GELLO 静止噪声和操作员意图测试后确定，不能直接拍脑袋
写死。

### 6.4 恢复增量遥操

GELLO 是增量控制，因此操作员不需要把主手移动回自动动作开始前的位置。但自动
动作结束时，软件仍必须重新锚定增量基准，否则旧目标可能在恢复瞬间造成跳变：

1. 读取动作完成或取消时的真实 FR3 关节角。
2. 读取同一时刻的 GELLO 关节角。
3. 清空自动动作期间累计的 GELLO 增量。
4. 将 FR3 当前真实关节角设置为新的目标基准。
5. 将 GELLO 当前读数设置为新的输入基准。
6. 经过一帧或短时间的稳定检查后，恢复 TELEOP 输出。

动作成功、IK 失败、控制器拒绝、软件 STOP、脚踏取消和 GELLO 移动中断，都必须
走同一个 REBASE/恢复流程。

### 6.5 比赛运行反馈与故障处理

遥操界面至少需要显示：

- 当前状态：TELEOP、ARMED、SOLVING、MACRO、REBASE 或 FAULT。
- 当前加载动作、目标机械臂、速度和预计时间。
- IK 求解帧数、失败帧、最大关节跳变和最大关节速度。
- 脚踏连接状态和最近一次触发时间。
- 中断来源：GELLO 移动、脚踏、UI STOP、IK 失败或控制器故障。

任何自动动作失败都应优先保持机械臂、清除动作所有权并安全返回遥操；无法确认
控制器状态时进入 FAULT，不能自动恢复命令输出。

## 7. 推荐后续实施顺序

1. 用真机录制一条短动作并完成 5% 低速复现。
2. 验证多个不同起点，记录 KDL 成功率和动作质量。
3. 标定并切换到勺子 TCP。
4. 调整滤波、时间参数化、速度和连续性阈值。
5. 在假硬件验收现有 TELEOP/SOLVING/MACRO/REBASE 控制权状态机。
6. 测量并调整现有 0.08 rad GELLO 移动中断阈值和取消延迟。
7. 接入脚踏开关和消抖。
8. 在假硬件覆盖成功、IK 失败、STOP 和恢复遥操测试。
9. 单臂、低速、无接触地进行真机集成测试。
10. 加入勺子和食物环境，逐步提高到比赛速度。
11. 单次流程稳定后，再考虑循环、动作库选择和比赛快捷操作。

## 8. 比赛可用前的验收条件

- [ ] 真机零力矩拖动和退出切换稳定。
- [ ] 勺子负载、质心和 TCP 已确认。
- [ ] 同一动作在多个实际起点可重复执行。
- [ ] IK 不出现不可接受的肘部漂移或关节分支跳变。
- [ ] 低速及目标速度下均不超过关节速度、加速度和控制器限制。
- [ ] UI STOP、脚踏取消和 GELLO 移动中断都经过真机验证。
- [ ] 自动动作结束和取消后恢复遥操无关节目标跳变。
- [ ] 任意 IK/控制器故障都不会产生第二命令源或自动继续运动。
- [ ] 操作员能够从 UI 明确判断当前控制权和故障原因。
- [ ] 完整盛取流程经过多次重复测试并保存故障日志。

## 9. 主要代码位置

- `apps/arm_ui/main.py`：Arm UI、录制、IK 验证和低速试运行交互。
- `apps/arm_ui/runtime.py`：ROS 状态、TF、控制器切换、KDL IK、轨迹执行与取消。
- `apps/arm_ui/recording.py`：动作样本、相对位姿计算和 YAML 持久化。
- `apps/arm_ui/test_recording.py`：动作数据和相对位姿测试。
- `apps/arm_ui/test_runtime_helpers.py`：低速轨迹辅助逻辑测试。
- `ros_ws/src/lychee_teach_controllers`：零力矩拖动控制器。
- `ros_ws/src/lychee_fr3_moveit_config/config/kinematics.yaml`：左右臂 KDL 配置。
- `ops/run/run_moveit.sh`：互斥检查、MoveIt/Arm UI 启动和浏览器自动打开。
